# LoopSieve — повторная проверка надёжности

20 ноября 2026 года, Arch Linux, Python 3.14.10. Исходный набор из 149 тестов прошёл до изменений. Затем были воспроизведены три дефекта и проверены соседние сценарии отказа.

| Проблема | Исправление | Результат |
|---|---|---|
| Из 12 одновременных проверок в счётчик попадала одна | Общий JSON обновляется под блокировкой ОС. Запуск самих проверок остаётся параллельным. | 12 параллельных CLI-процессов завершились успешно, в отчёте 12 запусков и 12 успешных проверок. Принудительный выход владельца блокировки не мешает следующему запуску. |
| Некорректные записи массива `checks` молча пропускались | Конфигурация проверяется до запуска команд. Ошибка указывает индекс и поле. Дубликаты имён, неверные типы и недопустимые лимиты отклоняются. | `check` и `report` возвращают код 2 с сообщением. Некорректный payload хука не прерывает работу вызывающего процесса. |
| Результат попадал в кеш после изменения входа во время проверки | Для кешируемого успешного запуска сверяются снимки до и после выполнения. Короткая трассировка сохраняется, в длинной выдержке остаётся конец лога. | Регрессии покрывают разные столбцы, пути с пробелами, последнюю ошибку, нечётный байтовый лимит и имя файла с дефисом. |

## Проверка после изменений

- **161 тест прошёл**. Команда `PYTHONPATH=src python3 -W error::ResourceWarning -m unittest discover -s tests -v`. Добавлены 12 регрессий в [test_verification_reliability.py](../tests/test_verification_reliability.py).
- Живой повторный запуск **локальной модели на CPU** через `check --explain` подтвердил исходный сбой, тот же совет при повторе и сохранение кода 1 после отключения сервера. В отчёте сохранились все три запуска и два подавления повторного лога.
- Три offline-фикстуры сохранили результаты. Повторяющийся лог сокращён с 19 144 до 2 911 символов. Оба набора с различающимися диагностическими расположениями сохранили исходный объём.
- Проверены форматирование и статический анализ Ruff, компиляция Python, синтаксис GitHub Actions через actionlint и запуск интерфейса Textual без интерактивного терминала.
- Собраны и проверены wheel и sdist. Wheel установлен в чистое окружение из локального файла, веса модели отсутствуют в архивах.

## Границы проверки

На этом этапе тесты и живой запуск повторены на Linux. Windows, macOS и CUDA-бенчмарк этого этапа не запускались. Это историческая проверка. В актуальной сборке веса задаются пользователем отдельно. Положительный кеш остаётся опциональным и требует полного объявления входов. Сравнение двух снимков не видит временную подмену входа с восстановлением идентичного содержимого между снимками. Состояние в разных сторонних инструментах и на сетевых файловых системах не проверялось. Действующая база Git в рабочей копии по-прежнему недоступна. [Матрица готовности](release-readiness.md).
