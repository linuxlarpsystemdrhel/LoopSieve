## Аудит безопасности и качества

- **Ввод и маршрутизация.** Ветка объяснений использует числовой loopback, прямой HTTP без прокси, лимиты SSE и контроль завершения потока. Из ответа убираются управляющие символы терминала. Ollama-адаптер отклоняет редиректы и обходит прокси. Hugging Face и совместимый адаптер отправляют bearer-заголовок только в первоначальном запросе.
- **Результаты и ресурсы.** Проверки выполняются через argv и `shell=False`. Основной runner перестал ждать POSIX-потомка, который удержал pipe после завершения ведущего процесса. Release-check использует тот же ограниченный вывод. Windows-ветка ограничивает ожидание фонового reader, но потомки, пережившие ведущий процесс, могут временно сохранить pipe.
- **Рабочее пространство.** Путь диагностики за пределами проекта больше не читается для построения AST-якоря. Сохраняется точное расположение ошибки. Контроль путей и разрешений в legacy runtime опирается на доверие к пользователю и локальному дереву. Отдельные процессы, которые намеренно меняют окружение, требуют изоляции средствами ОС.
- **Состояние и конфиденциальность.** JSON обновляется под межпроцессной блокировкой с атомарной заменой файла. При проблемах записи CLI сохраняет фактический результат проверки и выводит предупреждение. SQLite используется для журналов и доказательств. Вывод проверок, история и локальные кеши могут содержать секреты, если их напечатал сам инструмент. Точечный поиск распространённых форматов ключей в релизном дереве нашёл только строку в тестовой фикстуре. Историю Git проверить невозможно.
- **Десериализация и модель.** Новый путь разбирает JSON/SSE, принимает только текст в ожидаемых полях и не исполняет вывод модели. Локальный запуск загружает указанный GGUF и может сверить его SHA-256. Advisory-ответ не выдаёт разрешения и не меняет код возврата проверки.
- **Зависимости.** Ядро Python использует стандартную библиотеку. `pip check` прошёл, `pip-audit` не нашёл известных уязвимостей у проверенных установленных зависимостей, включая Textual 8.2.8. Строка самого неопубликованного LoopSieve в базе PyPI пропущена. llama.cpp устанавливается отдельно и требует отдельной проверки обновлений. [Результат pip-audit](../experiments/dependency-audit.json), [бюллетени llama.cpp](https://github.com/ggml-org/llama.cpp/security/advisories).

## Перед будущей публикацией

Для первого коммита создать локальный Git-репозиторий или использовать оригинальную Git-базу, если нужна старая история. В фактическом индексе повторно проверить файлы после любых изменений. Текущие workflow собирают и проверяют артефакты.

**Статус — публичная альфа подготовлена локально.** Проверка временного индекса относится только к текущему снимку. Публикация остаётся действием владельца.
