# GitHub growth forecast

Date: 2026-11-09

This is a product forecast, not a statistical guarantee. It assumes a public release with the current MVP polished, Windows/macOS/Linux CI passing, a real-repository benchmark published, and active issue response.

## Why the 10k probability is not higher

Several adjacent tools have reached tens of thousands of stars, but most had one or more of these advantages:

- a much larger total addressable audience;
- an obvious full-agent demo;
- a creator with an existing following;
- first-mover timing;
- a viral visual interface;
- a broader use case than verification.

LoopSieve's narrower scope is a product strength but a growth constraint.

## What would materially improve the forecast

The 365-day 10k estimate could move into the 15% to 25% range if all of the following became true:

1. A public benchmark on real repositories showed a repeatable reduction in redundant model-facing diagnostics without lower task success.
2. Installation became one command or one official plugin marketplace action.
3. The tool expanded to at least Codex CLI and OpenCode without becoming a large agent framework.
4. A visual demo showed a repeated failure loop collapsing from large logs to one compact evidence line.
5. Maintainers shipped fixes quickly and accepted high-quality contributors.

The estimate should move down if the real benchmark shows little effect on model turns or if Claude Code adds equivalent native behavior.

## Comparable adoption signals

The current ecosystem demonstrates that developer interest is large enough for focused extensions to spread quickly. Beads, ccusage, agent catalogs, multi-agent managers, and coding CLIs have all shown substantial organic growth. It also demonstrates intense competition.

The correct launch claim is therefore not "built for 10,000 stars." It is "here is a reproducible problem, here is the code, and here is what changed in the benchmark."
